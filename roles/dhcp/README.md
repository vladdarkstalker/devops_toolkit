# Роль `dhcp`

Роль разворачивает `isc-dhcp-server` и выдаёт PXE-клиентам сетевые параметры, адрес TFTP-сервера и загрузчик, соответствующий типу прошивки клиента. Она может запускаться отдельно через `playbooks/dhcp.yaml` или как заключительный этап `playbooks/pxe.yaml`.

## Границы ответственности

Роль отвечает только за DHCP. Она не устанавливает TFTP, не создаёт загрузочное меню и не публикует образы. Значение `dhcp_tftp_server` должно указывать на уже подготовленный TFTP-сервер.

Роль:

1. обновляет индекс APT с часовым кэшем;
2. устанавливает пакеты из `dhcp_packages`;
3. копирует существующий `/etc/dhcp` в каталог резервных копий с временной меткой;
4. генерирует candidate `/etc/dhcp/dhcpd.conf.ansible`, проверяет его командой `dhcpd -t` и только после успеха заменяет рабочий `/etc/dhcp/dhcpd.conf`;
5. генерирует `/etc/default/isc-dhcp-server` с перечнем интерфейсов;
6. перезапускает службу только при изменении конфигурации;
7. включает `isc-dhcp-server` в автозагрузку и запускает её.

## Требования

- Debian/Ubuntu-подобная целевая система с APT и systemd;
- повышение привилегий через `become`;
- статический адрес DHCP-сервера;
- отсутствие другого DHCP-сервера в том же широковещательном домене, если их работа специально не согласована;
- существующая inventory-группа `[dhcp_servers]`.

## Выбор загрузчика

Шаблон использует DHCP option 93 (`client-system-arch`):

| Архитектура клиента | Код | Возвращаемый файл |
|---|---:|---|
| Legacy BIOS | `00:00` | `BIOS/pxelinux.0` |
| UEFI IA32 | `00:06` | `EFIia32/syslinux.efi` |
| UEFI x64 | `00:07`, `00:09` | `EFIx64/syslinux.efi` |

Текущая роль `tftp` публикует BIOS и UEFI x64. Каталог и файлы UEFI IA32 пока необходимо добавлять отдельно либо не использовать этот тип клиентов.

## Переменные

Источник значений по умолчанию — `roles/dhcp/defaults/main.yaml`. В штатных playbook сетевые параметры переопределяются общим файлом `playbooks/vars/pxe.yaml`.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `dhcp_packages` | `[isc-dhcp-server]` | Устанавливаемые пакеты |
| `dhcp_subnet` | `192.168.0.0` | Адрес обслуживаемой сети |
| `dhcp_netmask` | `255.255.255.0` | Маска сети |
| `dhcp_range_start` | `192.168.0.100` | Первый динамический адрес |
| `dhcp_range_end` | `192.168.0.200` | Последний динамический адрес |
| `dhcp_broadcast_address` | `192.168.0.255` | Broadcast-адрес |
| `dhcp_gateway` | `192.168.0.1` | Шлюз, передаваемый клиентам |
| `dhcp_dns_servers` | `.2`, `.3` в defaults | Список DNS-серверов; общий PXE-файл задаёт `.24` |
| `dhcp_tftp_server` | `192.168.0.24` | Значение директивы `next-server` |
| `dhcp_interfacesv4` | `[]` | Интерфейсы службы; пустой список означает все IPv4-интерфейсы |
| `dhcp_backup_path` | `/opt/backups/dhcp` | Корень резервных копий |
| `dhcp_backup_dirs` | `[/etc/dhcp]` | Каталоги, копируемые до изменения |
| `dhcp_user`, `dhcp_group` | `root` | Владелец сгенерированного `dhcpd.conf` |

Все поля подсети должны описывать одну и ту же сеть. При смене адресации недостаточно изменить только `dhcp_subnet`.

Пример для выделенного PXE-интерфейса:

```yaml
dhcp_interfacesv4:
  - ens19
```

Имя интерфейса можно узнать на целевом сервере командой `ip -br link`. Если у сервера есть интерфейс управления и отдельный PXE-интерфейс, рекомендуется явно указать только PXE-интерфейс.

## Inventory и запуск

```ini
[dhcp_servers]
pxe01 ansible_host=192.168.0.24 ansible_user=user
```

```bash
ANSIBLE_CONFIG="$PWD/ansible.cfg" ansible-playbook \
  -i playbooks/inventory.ini playbooks/dhcp.yaml \
  --limit pxe01 --ask-become-pass
```

## Управляемые файлы и служба

| Объект | Назначение |
|---|---|
| `/etc/dhcp/dhcpd.conf.ansible` | Candidate-файл, доступный `dhcpd` при действующем AppArmor и проверяемый до применения |
| `/etc/dhcp/dhcpd.conf` | Подсеть, пул адресов, DNS, gateway и выбор PXE-загрузчика |
| `/etc/default/isc-dhcp-server` | Перечень прослушиваемых IPv4-интерфейсов |
| `/opt/backups/dhcp/` | Копии исходной конфигурации |
| `isc-dhcp-server` | Управляемая systemd-служба |

Роль полностью управляет двумя конфигурационными файлами. Ручные изменения в них при следующем запуске могут быть заменены шаблонами.

## Связь с другими ролями

- `dhcp_tftp_server` должен совпадать с адресом узла из `[tftp_servers]`.
- Пути загрузчиков должны существовать внутри `tftp_root`.
- `dhcp_dns_servers` должен содержать адреса узлов из `[dns_servers]`, если клиенты используют DNS проекта.
- В полном сценарии DHCP выполняется последним, чтобы клиент не получил ссылки на ещё не опубликованные файлы.
